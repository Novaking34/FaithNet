== The Session 006 Lesson: When a Safety Lock Saves the Machine

During Playtest Session 006, an everyday real-world action triggered a classic
multi-system edge case: switching `wlp3s0` from `TheTribe` (Channel 11) to a
mobile phone hotspot while `hostapd` still held virtual interface `ap0` pinned
to Channel 11 on the single-radio `RTL8852CE` (`rtw89`) Wi-Fi card.

Notice **what happened** — and even more importantly, **what did NOT happen**:

* **What happened:** The `rtw89` driver and PCIe Wi-Fi firmware detected an
  illegal concurrent dual-channel request on single-channel silicon (`#channels
  <= 1`), tripped an internal hardware safety lock, and refused further radio
  commands until power-cycle reset.
* **What did NOT happen:** The laptop did not suffer a kernel panic, filesystem
  corruption, fried RF state, or broken permanent NetworkManager profiles. **A
  single clean reboot restored 100% of host networking in seconds.**

Why did a reboot fix everything cleanly? Because **both the silicon AND our
Field Kit scripts obeyed a non-destructive containment discipline**:

1. **Zero Permanent Mutation of `wlp3s0`:** Our scripts never rewrote
   `/etc/NetworkManager/system-connections/`, never uninstalled `NetworkManager`,
   never hijacked `systemd-resolved` globally, and never persisted raw
   `iptables-save` rules to `/etc/iptables/`.
2. **Scoped Runtime State Only:** All AP configs (`hostapd.conf`, `dnsmasq.conf`,
   leases, PIDs) lived inside ephemeral `/run/faithnet-ap/` (RAM-backed `tmpfs`)
   and all NAT/forwarding rules were scoped strictly to `-i ap0` / `-o ap0`.
3. **Hardware Safety Lock as a Feature, Not a Catastrophe:** Just like a circuit
   breaker in a house trips *before* the wires catch fire, a well-designed
   safety lock halts an unsafe transition cleanly while preserving a known-good
   recovery baseline.

== Why "Graceful Degradation" Beats "Hard Abort" in Sovereign Systems

Commercial cloud software often assumes an infinite, always-on, centrally
managed infrastructure — so when a dependency fails, it throws a fatal error and
exits (`os.Exit(1)`). **A sovereign offline-first substrate cannot afford that
mentality.**

When power fluctuates, Wi-Fi roams, a browser refuses HTTP, or a cable gets
yanked mid-conversation, **aborting leaves humans stranded in silence.**
Graceful degradation instead asks: *"What is the highest safe capability we can
still hold right now without harming the host or leaking trust?"*

== Design Rules Forged From Field Kit 01

Every future FaithNet wave and MillenniumOS Track 0 driver now inherits five
non-negotiable safety laws proved in Field Kit 01:

1. **The Containment Law:** Any experimental or dynamic networking feature must
   isolate its runtime state (dedicated interface `ap0`, dedicated `/run/`
   directory, scoped firewall rules) so tearing it down restores the host to
   byte-for-byte pre-run behavior.
2. **The Yield-Before-Fight Law:** When sharing finite hardware (one Wi-Fi
   radio, one audio card, one UART), secondary services must yield *before*
   primary state transitions begin (event-driven `nmcli monitor`), never race
   afterward via slow polling.
3. **The Sole-Link Survival Law:** Graceful degradation may step down from
   Rung 4 -> 3 -> 2 -> 1, and may temporarily cool down a silent link when a
   backup exists, but **must never sever the sole remaining communication path.**
4. **The Zero-Scare Psychology Law:** User-facing security must degrade cleanly
   (Tier 3 -> Tier 2 -> Tier 1) without terrifying non-technical community users
   or forcing them to disable browser protections.
5. **The Firewalled-Uplink Sovereignty Law *(PROVEN LIVE IN S007!)*:**  
   `FaithNet-HomeRoom` (`ap0` + `lo` + local split-DNS `faithnet.lan`) is the
   host PC's primary sovereign identity, while commercial `wlp3s0` is isolated
   behind a **dual-stack IPv4+IPv6 inbound firewall (`FAITHNET_WAN_GUARD`)**
   with an instant zero-reboot **`island` / `bridge`** egress toggle and
   automatic **Zero-`TheTribe` standalone Channel 6 fallback** (`t = 12s`).
